# dsh-tripsy

在 **DeepSeek Harness** 里直接浏览你的 **[Tripsy](https://tripsy.app)** 行程：日程、活动、住宿、交通、费用——并且**按各条目自己的时区**显示时间。

## 它做什么

侧栏多一行，中栏多一页。

**＋ 新建行程** 就在行程列表最上方。用自然语言描述你想怎么玩——去哪、几天、和谁、什么偏好——面板会拼出一条详细指令，由 agent 变成一份真实行程：**先建行程本身，再按天补上活动、住宿和交通**。

**选中一个行程后，两个模块都在它里面：**

- **行程浏览** —— 封面头图 + 行程名 + 倒计时 + 天数 + 日期区间；**按天分组的行程轴**，每一项带自己的图标；**费用概览卡片**按类别从各条目自己的价格汇总并给出总计。所有时间都按该条目自己的 IANA 时区渲染。
- **AI 管理** —— 用大白话描述你想改什么。面板会为**这个行程**拼出一条精确指令（含 id、日期、时区），**放进 DSH 的对话输入框**，由 agent 用 Tripsy MCP 工具执行，每一步你都看得见。**两个模块都不会直接写你的账号。**

**账号信息不会下发到浏览器。** `/api/dsh-tripsy/health` 只返回授权摘要与账户货币，**不包含** Tripsy 资料里的姓名、邮箱和头像。

## 安装

```sh
dsh plugin --profile web add github:ta-www/dsh-tripsy
```

刷新页面，侧栏就会出现 **Tripsy**。第一次点「登录 Tripsy」，浏览器打开一次完成 OAuth 授权；之后令牌自动续期，不用再管。

## 费用：由 AI 补全

Tripsy 自带的费用统计需要付费方案，所以面板改为使用**活动、住宿、交通上已有的价格**。每个行程里的 **费用概览** 卡片汇总已填价格的部分，**AI 计算费用** 则把一条指令交给 agent 去补全。

这个分工是刻意的：**求和是算术**，所以在宿主半精确地算一次并被测试覆盖；**估算没填价格的部分是判断**，所以交给 agent——但会把真实数字一并带上，并要求它直接采用而不是重新估、不确定就直说而不是编造精度、**绝不假设汇率**。多币种分开列出，不会悄悄加成一个数字。

指令里还写明**不要改动行程**：这只是一份报告，不是一次写入。

## 导出到日历（ICS）

每个行程的名称旁边都有 **导出到日历**，以及一个 **教程** 按钮，点开就在原地显示导入步骤——「导出」和「怎么导进手机」这两半分开讲没有意义。

`GET /api/dsh-tripsy/ics?id=<行程id>` 返回一个 `text/calendar` 文件：

- 行程本身是一条**跨多天的全天事件**，结束日按 ICS 规范**排他**写入（+1 天），最后一天不会丢
- 每个活动、住宿、交通各一条事件，带 `LOCATION`、`GEO`、确认号、价格与备注
- **没有开始时间的条目会被跳过**，跳过条数在 `X-Tripsy-Skipped` 里报告

**时间用的是 UTC 绝对时刻，而不是绑定时区名的壁上时间。** 绑 `TZID` 必须同时给出该时区真实的 `VTIMEZONE`（含夏令时转换），手写极易出错、导入后会偏一小时；UTC 任何日历都不会解析错，飞行时长也准确。当地时间会写进每条事件的描述里，所以行程读起来仍和预订单一致。

iPhone 上的做法：存下 `.ics`，交给快捷指令（社区里的 *ICS To Calendar*，或自己建三个动作：接收「文件」→「选择日历」→「添加新日程」），也可以直接点开文件让 iOS 问你要加到哪个日历。

## 实现方式

宿主半注册一族小路由，并**复用 [tripsy-mcp](https://github.com/ta-www/tripsy-mcp) CLI 里同一份 OAuth + MCP 代码**，因此 OAuth 只有一份实现、令牌只有一处刷新。

| 文件 | 作用 |
|---|---|
| `lib/index.js` | 宿主半：`/api/dsh-tripsy/{health,trips,trip,login}` |
| `lib/client.js` | 浏览器半：侧栏行与面板页 |
| `lib/tripsy/*.mjs` | OAuth 2.1（PKCE + 动态客户端注册）、Streamable HTTP MCP 客户端 |
| `cordis.patch.yml` | 插入插件行 |

凭据落盘在 `$DSH_HOME/tripsy-auth.json`（可用 `authFile` 配置项覆盖）。**令牌永远不会发到浏览器**——面板只能看到数据，看不到令牌。

请求默认只接受本机回环来源。如果你确实要通过局域网地址访问 UI，把插件配置里的 `allowRemote` 设为 `true`。

## 配置

```yaml
- id: ui-tripsy
  name: dsh-tripsy
  config:
    authFile: 'C:\Users\you\.dsh\tripsy-auth.json'   # 令牌存放位置
    allowRemote: false                               # 保持仅本机可访问
    enabled: true
```

## 说明

- 需要有效的 Tripsy 账号。文档附件类功能需要 Tripsy Pro，其余免费账号即可。
- Tripsy 以 UTC 存储时间，本插件按各条目自己的 IANA 时区渲染——这正是上游 API 要求客户端做的事。
- 非官方社区插件，与 Tripsy 无隶属关系。
